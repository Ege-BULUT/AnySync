How Any~Sync works

From the first run to the brief your agent finishes.

Status

AnySync 0.1.0 is out: get it on the Download page. Working today: device identity and looks for all three systems, the bus repo, the item catalogue with per-system paths, offers and picks, the encrypted device to device stream with resume, placing and the brief, in the window and on the command line. CI tests and builds it on Windows and Linux; macOS is tested where it is built.

What you need

  • Two computers running AnySync, each on macOS, Windows or Linux.
  • One GitHub account, signed in with the GitHub CLI (gh auth login) on both, or a token in ANYSYNC_TOKEN.
  • The two on the same network, so they can reach each other directly.
  • For the last step, any AI agent you like to read GOAL.md.

First run

AnySync gives the device a random eight digit id and keeps it, the name, the look and a key pair in its own folder: ~/.config/anysync, or %APPDATA%\anysync on Windows. On first use it makes your private bus repo, <login>/anysync-bus, and registers the device there with its system and public key.

Connect

On the Connect tab, press Find devices on this account and pick the other computer. Choose to send or to receive; the other device shows the request, and its owner approves or declines. The direction holds for this transfer only.

Pick and move

The sender offers a tree of what it has, grouped by kind. Each item shows where it lands on the receiver's system, or that it has no place there. Tick what you want; only those travel, straight between the two devices. Folders rebuilt from source (node_modules, target, .venv, __pycache__ and the like) stay behind. If the connection drops, the receiver asks again for what has not arrived, up to 20 times.

Where things land

Every item has a logical id, like editors/vscode, and a list of paths per system. The sender packs each item under its id, never under its own paths; the receiver unpacks into a staging folder and moves each part to its own path for that item. Whatever was there is kept next to it as <name>.before-anysync. Each transfer gets a folder at ~/AnySync/<transfer>, with the lists in lists/.

The brief

When everything is in place, the receiver writes GOAL.md into the transfer folder: every item, where it landed, any problems, a note on what is left to do for each, and, when the systems or home folders differ, which paths to rewrite. Hand it to the agent you use, for example:

cd ~/AnySync/<transfer> && claude "Read GOAL.md in this folder and do what it says."

On a Mac, AnySync also writes preflight.sh when the picks need tools: it installs Apple's command line tools, Homebrew and Node where they are missing, without sudo for Node. Done means every item works, or is in TODO-FOR-YOU.md with steps.

Security

The small things on GitHub (the offer, the picks, the stream key) are sealed boxes to the other device's public key (X25519, XSalsa20-Poly1305). Files go as an XChaCha20-Poly1305 stream under a random key only the two devices know; every frame is authenticated, so a wrong key gets nothing and a cut stream fails instead of ending early.

Command line

anysync                               open the window
anysync --scan                        what this device could send
anysync --give <id> [--only a,b]      ask device <id> to receive, then send
anysync --accept [--only a,b]         approve the request waiting here, then do this side
anysync --id                          this device's id, name and look

--only takes item ids or their starts, as --scan lists them; without it the receiver takes everything that has a place on its system.
